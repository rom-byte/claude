# 📚 다했니 독서 기록장 — 제품 요구사항 문서 (PRD)

| 항목 | 내용 |
|---|---|
| 문서 버전 | v1.0 |
| 작성일 | 2026-07-12 |
| 제품명 (가칭) | 다했니 독서 기록장 (Dahandin Reading Log) |
| 연동 API | 다했니 Open API v1 (`https://api.dahandin.com/openapi/v1`) |
| 대상 사용자 | 초·중등 학생, 담임/교과 교사 |

---

## 1. 개요 및 배경

학생들이 읽은 책을 기록하고 감상을 남기는 "독서 기록장"을 디지털로 옮긴 웹 서비스입니다.
학급 보상 시스템인 **다했니(Dahandin)** 와 연동하여, 학생은 별도의 회원가입 없이
**학생 코드**만으로 로그인하고, 자신의 **쿠키(보상) 내역·초코칩·뱃지**를 독서 기록장 안에서
함께 확인할 수 있습니다.

### 해결하려는 문제

- 종이 독서 기록장은 분실되기 쉽고, 교사가 학급 전체의 독서 현황을 한눈에 보기 어렵다.
- 독서 활동과 학급 보상(쿠키)이 분리되어 있어, 학생 입장에서 "책을 읽으면 보상으로 이어진다"는
  동기 연결 고리가 약하다.
- 저학년 학생에게 아이디/비밀번호 방식의 로그인은 진입 장벽이 크다.

### 핵심 가치 제안

> "학생 코드 하나로 로그인하고, 책을 기록할수록 나의 다했니 쿠키·뱃지와 함께 성장하는 독서 기록장"

---

## 2. 목표 및 성공 지표

### 2.1 제품 목표

1. 학생이 30초 안에 로그인하고 1분 안에 첫 독서 기록을 남길 수 있다.
2. 다했니 쿠키/초코칩/뱃지 현황을 독서 기록장 안에서 실시간에 가깝게 확인할 수 있다.
3. 교사가 학급 단위 독서 현황과 다했니 클래스 쿠키 현황을 한 화면에서 파악할 수 있다.

### 2.2 성공 지표 (KPI)

| 지표 | 목표치 |
|---|---|
| 학생 1인당 월평균 독서 기록 수 | 4권 이상 |
| 주간 재방문율 (학생) | 60% 이상 |
| 첫 기록까지 소요 시간 (중앙값) | 90초 이내 |
| API 오류(429 포함)로 인한 화면 실패율 | 1% 미만 |

## 3. 사용자 및 페르소나

### 3.1 학생 (주 사용자)

- 초등 3학년 ~ 중학생. 타이핑이 느리고 긴 양식을 싫어함.
- 다했니 학생 코드는 교사에게 이미 발급받아 알고 있음.
- 니즈: 쉽고 재밌게 기록하고, 기록한 만큼 보상(쿠키·뱃지)이 눈에 보였으면 함.

### 3.2 교사 (관리자)

- 다했니를 학급 운영에 이미 사용 중이며 Open API 키를 발급받을 수 있음.
- 니즈: 학급 전체 독서 현황 파악, 성실히 기록한 학생에게 다했니 쿠키로 보상.

## 4. 기능 요구사항

### 4.1 학생 코드 로그인 (P0)

- 로그인 화면에는 **학생 코드 입력란 하나**만 존재한다. (아이디/비밀번호 없음)
- 입력된 코드로 서버가 다했니 `GET /get/student/total?code={학생코드}` 를 호출하여
  `result: true` 이면 로그인 성공으로 처리하고, 응답의 `name`, `number` 를 세션에 저장한다.
- `result: false` (존재하지 않는 코드 등) 이면 "학생 코드를 다시 확인해 주세요" 안내를 표시한다.
- 로그인 성공 시 자체 세션 토큰(JWT 등)을 발급하고, 이후 요청은 이 토큰으로 인증한다.
- "코드 기억하기" 옵션: 기기(브라우저)에 코드를 저장해 다음 방문 시 자동 로그인.
- 무차별 대입 방지: 동일 IP 기준 로그인 시도 분당 10회 제한.

### 4.2 내 다했니 현황 대시보드 (P0)

로그인 직후 홈 화면 상단에 다했니 연동 정보를 카드로 표시한다.

- **쿠키 카드**: `cookie`(전체), `usedCookie`(사용), `totalCookie`(남은 쿠키)를
  진행 바/도넛 형태로 시각화.
- **초코칩 카드**: `chocoChips` 개수 표시.
- **뱃지 진열장**: `badges` 객체를 순회하여 전체 뱃지 목록을 표시하되,
  `hasBadge: false` 인 뱃지는 흑백(잠금) 처리하여 수집 욕구를 자극한다.
- 데이터는 서버가 다했니 API에서 조회 후 캐시(TTL 5분)하여 내려준다. (Rate Limit 대응, §6.3)
- 다했니 API 장애 시에도 독서 기록 기능은 정상 동작해야 하며, 카드 영역에만
  "다했니 정보를 불러오지 못했어요" 안내를 표시한다.

### 4.3 독서 기록 작성·관리 (P0)

독서 기록 데이터는 다했니가 아닌 **자체 데이터베이스**에 저장한다.

- 기록 항목: 책 제목(필수), 지은이, 읽은 날짜(기본값: 오늘), 읽은 쪽수 또는 완독 여부,
  별점(1~5), 감상문(선택, 최소 글자 제한 없음), 표지 이미지(선택).
- 저학년 배려: 감상문 대신 **이모지 스티커**(😆 재밌어요 / 😢 슬펐어요 / 😮 놀라워요 등)만
  골라도 기록이 완성되도록 한다.
- 자신의 기록 목록을 최신순으로 보고, 수정·삭제할 수 있다.
- 검색/필터: 제목 검색, 월별 필터, 별점 필터.

### 4.4 독서 목표와 챌린지 (P1)

- 학생이 월간 목표 권수(예: "이번 달 5권")를 설정하고, 진행률을 진행 바로 확인한다.
- 교사가 학급 공통 챌린지(예: "여름방학 10권 읽기")를 개설하면 학급 전체 진행률이 표시된다.
- 목표 달성 시 축하 애니메이션과 함께 "달성 카드"가 발급된다.
  (실제 쿠키 지급은 다했니 API가 쓰기를 지원하지 않으므로, 교사에게 달성 알림을 보내
  교사가 다했니 앱에서 직접 쿠키를 지급하는 방식 — §9 오픈 이슈 참고)

### 4.5 독서 통계 (P1)

- 학생용: 월별 읽은 권수 막대 그래프, 누적 권수, 연속 기록 일수(스트릭), 별점 분포.
- "독서 달력": 기록이 있는 날짜에 스탬프가 찍히는 달력 뷰.

### 4.6 교사용 학급 관리 (P1)

- 교사는 별도 교사 계정(이메일 로그인)으로 접속하고, 본인의 다했니 **API 키를 등록**한다.
- `GET /get/class/list` 를 호출하여 교사가 가진 클래스 목록(`name`, `totalCookies`,
  `cookies`, `usedCookies`)을 표시한다.
- 학급 학생 명단(학생 코드 등록)을 관리하고, 학생별 독서 기록 수·최근 기록·목표 달성 여부를
  표 형태로 조회한다.
- 학생 감상문 열람 및 교사 댓글(칭찬 한마디) 작성.
- 우수 독서 학생 목록을 뽑아 "쿠키 지급 추천 리스트"로 내보내기(CSV) — 교사가 다했니에서
  수동 지급 시 참고.

### 4.7 기록장 내보내기 (P2)

- 학기말에 학생별 독서 기록장을 **PDF로 내보내기** (표지 + 기록 목록 + 통계 요약).
- 생활기록부 참고용으로 교사가 학급 전체 요약본을 일괄 다운로드.

### 4.8 책 정보 자동 완성 (P2)

- 책 제목 입력 시 외부 도서 API(예: 알라딘/카카오 책 검색)로 서지 정보·표지를 자동 완성.
- 외부 API 미연동 상태에서도 수동 입력으로 완전히 동작해야 한다.

## 6. 시스템 및 API 연동 설계

### 6.1 아키텍처

```
[학생/교사 브라우저]
        │  (자체 세션 토큰)
        ▼
[독서 기록장 백엔드 서버] ──── 자체 DB (독서 기록, 목표, 챌린지, 교사 계정)
        │  (X-API-Key — 서버에만 보관)
        ▼
[다했니 Open API]  /get/student/total, /get/class/list
```

### 6.2 API 키 보안 (필수)

- **X-API-Key는 절대 프론트엔드(브라우저) 코드에 포함하지 않는다.**
  설명서의 JavaScript fetch 예제처럼 브라우저에서 직접 호출하면 키가 노출되므로,
  모든 다했니 API 호출은 백엔드 프록시를 경유한다.
- 교사가 등록한 API 키는 서버에 암호화하여 저장한다.
- API 키 오류 응답(`"API KEY 가 올바르지 않습니다."`) 수신 시 교사에게
  "API 키를 다시 등록해 주세요" 알림을 보낸다.

### 6.3 Rate Limit 대응 (평균 5 req/sec, 300 req/min)

- 서버 측 **캐싱**: 학생 정보(`/get/student/total`) TTL 5분, 클래스 목록 TTL 10분.
  동일 학생의 반복 조회는 캐시로 응답한다.
- 서버 측 **스로틀링**: 다했니 호출 큐를 두고 초당 최대 3~4건으로 제한 (안전 속도).
- 교사 대시보드에서 학급 전체(예: 30명) 조회 시 **일괄 병렬 호출 금지** —
  요청당 200ms 간격의 순차 처리 + 진행률 표시.
- `429` 또는 `{"result": false, "message": "slow down."}` 수신 시
  지수 백오프(1s → 2s → 4s, 최대 3회) 후 재시도, 최종 실패 시 캐시된 값으로 대체 표시.

### 6.4 사용 API 정리

| 용도 | 엔드포인트 | 호출 시점 |
|---|---|---|
| 학생 로그인 검증 + 프로필/쿠키/뱃지 | `GET /get/student/total?code={코드}` | 로그인 시, 홈 진입 시(캐시 만료 시) |
| 교사 클래스 목록 + 클래스 쿠키 현황 | `GET /get/class/list` | 교사 대시보드 진입 시(캐시 만료 시) |

### 6.5 자체 데이터 모델 (요약)

- **Student**: 학생 코드(다했니 code, 고유), 이름·번호 스냅숏, 소속 학급
- **ReadingRecord**: 학생 참조, 책 제목, 지은이, 읽은 날짜, 별점, 이모지, 감상문, 표지 URL
- **Goal / Challenge**: 대상(개인/학급), 기간, 목표 권수, 진행 상태
- **Teacher**: 이메일 계정, 암호화된 다했니 API 키, 소유 학급 목록
- **TeacherComment**: 기록 참조, 교사 참조, 내용

## 7. 비기능 요구사항

- **개인정보**: 저장하는 학생 정보는 다했니 학생 코드·이름·번호와 독서 기록으로 최소화.
  학생 코드는 로그에 평문으로 남기지 않는다. 교사 요청 시 학생 데이터 일괄 삭제 지원.
- **성능**: 홈 화면 로딩 2초 이내(캐시 적중 시), 기록 저장 응답 500ms 이내.
- **가용성**: 다했니 API 장애가 독서 기록 CRUD를 막지 않는다 (연동 영역만 성능 저하 허용).
- **접근성**: 키보드만으로 기록 작성 가능, 명도 대비 WCAG AA, 큰 터치 타깃(44px+).
- **브라우저**: 최신 Chrome/Edge/Safari + 학교 태블릿(안드로이드/iPad) 지원.

## 9. 오픈 이슈 / 확인 필요 사항

1. **쿠키 자동 지급 불가**: 현재 Open API v1은 조회(GET)만 제공하므로 독서 기록 보상으로
   쿠키를 자동 지급할 수 없다. 다했니 측에 쿠키 지급 API(POST) 제공 여부 문의 필요.
   그 전까지는 "교사 알림 + 수동 지급" 플로우로 운영한다.
2. **학생 코드만으로 로그인하는 보안 수준**: 코드가 유출되면 타인이 열람 가능하다.
   학급 내 서비스 특성상 허용 가능한 수준인지 교사 의견 수렴 필요.
   (완화책: 기기 기억 + 최초 로그인 시 교사 승인 옵션)
3. **학생 명단과 다했니 클래스 매핑**: `/get/class/list` 는 클래스별 학생 목록을 주지 않으므로,
   교사가 학생 코드를 직접 등록하거나 CSV 업로드하는 방식으로 시작한다.
   클래스별 학생 목록 API가 추가되면 자동 동기화로 개선.
4. **외부 도서 API 선정** (알라딘 vs 카카오): 키 발급 정책·무료 쿼터 비교 후 M4에서 결정.
